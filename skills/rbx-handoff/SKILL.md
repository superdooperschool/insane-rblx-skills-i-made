# rbx-handoff

**Two files, different jobs.** `STATUS.md` is overwritten every step and is the only thing the next
session reads. `HANDOFF.md` is appended and is for the human. An append-only log that the agent
re-reads grew 0 -> 41 KB in 13 cron cycles; a session that resumed without a handoff regressed 32
quests and a sell/spin race. Templates in `templates/`.

## Layout (per game, in the project folder)


| File | Written | Read by | Size |
|---|---|---|---|
| `STATUS.md` | overwritten at every milestone | the next session, first | 20-30 lines, constant |
| `HANDOFF.md` | appended per day/session | the user; the agent only for the rules block | grows |
| `PLAN.md` | drafted once, edited on scope change | the agent for the undone parts | stable |
| `MAP.md` | regenerated by rbx-map | grep only | large |

## STATUS.md contract (template: `templates/STATUS.md`)

Header line: `overwrite each step; detail in HANDOFF.md`. Then: user ask (one line); checklist with
`[x]` done + verified, `[~]` in progress, `[ ]` todo, `[-]` deferred on purpose, `[?]` built but NOT
verified; **Next action** (one line, exact command or edit); **Studio state** (Edit/Play, unsaved,
peer sessions and their owned paths); **Blockers**. Nothing else.

## HANDOFF.md contract (template: `templates/HANDOFF.md`)

Section 0 "Rules for whoever continues": place id, hard constraints (autosave or not, no
GlobalShadows...), style reference, tool paths, session gotchas. Then dated sections, each a table
`Item | What changed | Where | State` where State is one of `DONE verified`, `BUILT not verified`,
`already existed`, `reverted`. Open issues as `Open: ... Next: ...` in the same row. Ends with
"Remaining work (in order)" and "User-facing notes".

## Protocol

1. **Resume**: read `STATUS.md`. Read HANDOFF section 0 only. Grep MAP.md for the names in "Next
   action". Do not read the rest of HANDOFF; do not re-derive state from the place.
2. **Milestone** (a feature lands, a verify pass completes, ~150k context, before any risky step):
   rewrite STATUS.md, append one HANDOFF row per changed item with its verification state.
3. **Close**: STATUS.md says exactly what to do next and what is unverified. HANDOFF gets the
   user-facing notes. Memory gets one pointer: `RESUME: read <project>/STATUS.md`. Not the content.
4. **Unattended loops** (cron/overnight): each cycle reads STATUS.md only, appends to HANDOFF.md,
   overwrites STATUS.md. Brief says so explicitly. Heartbeat + recurring cron, since crons fire only
   when the REPL is idle.
5. **Unsaved work**: if the place does not autosave (Team Create keeps edits; some places
   need Ctrl+S), STATUS "Studio state" says `UNSAVED` and the user notes repeat it.

## Red flags

- "Let me read HANDOFF.md fully to understand where we are"
- STATUS.md longer than 30 lines, or containing history
- A `[x]` without evidence in the HANDOFF row
- Resuming by exploring the place instead of reading STATUS
- Memory note that restates STATUS instead of pointing at it
